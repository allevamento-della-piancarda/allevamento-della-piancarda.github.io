# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Static site for a dog breeding kennel ("Allevamento della Piancarda"), generated by a small Node script with zero dependencies — no npm install, no framework, no cookies or external services. Content is in Italian.

## Commands

- Build the site: `node build.js` — regenerates everything in `docs/` from scratch (the directory is wiped and recreated each run).
- Preview locally: `python3 -m http.server -d docs` or `npx serve docs`, then open http://localhost:8000.
- No test suite, linter, or package.json — there's nothing to install.

## Architecture

- `contenuti.js` — the single source of truth for all content (dogs, litters, contacts, copy). This is the **only** file meant to be edited for routine content updates.
- `build.js` — the static site generator. Reads `contenuti.js`, validates it, and writes HTML into `docs/`. Everything else below lives in this file.
- `src/css/`, `src/js/` — hand-written CSS and browser-side JS (mobile menu, photo lightbox zoom). Copied as-is into `docs/` during build.
- `img/` — source photos, copied into `docs/img/` during build (`.gitkeep` files are excluded).
- `docs/` — the fully generated, committed output, published directly by GitHub Pages from the `main` branch. **Never hand-edit files in `docs/`** — they're overwritten on every build. Commit `docs/` alongside source changes.

### Build-time validation

`build.js` validates `contenuti.js` before generating anything and aborts with a descriptive error (no output written) if:
- a dog `id` isn't lowercase letters/digits/hyphens
- two dogs share the same `id`
- a litter references a parent `id` that doesn't match any dog in `cani`

### Page generation model

`build.js` builds a `pagine` array of page descriptors (`{ percorso, titolo, descrizione, corpo, immagine }`), one per dog plus the fixed pages (home, `/cani/`, `/cucciolate/`, `/404.html`), and renders each through the shared `pagina()` shell (header/nav/footer/WhatsApp float/lightbox markup). Each descriptor's `corpo(rel)` function returns the page-specific HTML; `rel` is the relative path prefix back to site root (computed from URL depth) so the site works both on the real domain and from a local folder preview — `/404.html` is the one exception, using absolute `/` links.

Output routing: a `percorso` ending in `/` becomes `<percorso>/index.html`; otherwise it's written as a literal file (used only for `/404.html`).

After pages, the build also writes `sitemap.xml`, `robots.txt`, `CNAME` (derived from `contenuti.js`'s `sitoUrl`), and `.nojekyll`.

A cache-busting `VERSIONE` (based on build time) is appended as `?v=` on the CSS/JS links so browsers reload assets after each deploy.

### Content model (`contenuti.js`)

- `cani`: array of dogs. Each needs a unique `id` (lowercase/digits/hyphens) — this becomes the URL `/cani/<id>/`. Includes pedigree (`pedigree.padre`/`madre`, each with nested `padre`/`madre` names for grandparents), health test results (`salute`), show/work results (`risultati`, tagged `esposizione` or `lavoro`), and a photo gallery (`galleria`).
- `cucciolate`: array of litters, newest first — the first entry is the one shown on the home page. `padre`/`madre` can reference an existing dog via `id` (renders as a link) or just a plain name.
- Dates are `"AAAA-MM-GG"` (ISO `YYYY-MM-DD`); blank photo fields (`""`) render as a placeholder box instead of broken `<img>`.

### Publication switches

Two booleans at the top of `contenuti.js` gate the staged rollout — flip them, rerun `node build.js`, commit:
- `dominioAttivo` — when false, **no `CNAME` is written**. A `CNAME` pointing at an unregistered domain makes Pages redirect there and the site becomes unreachable, so this stays false until the domain resolves. Flip to true together with restoring the real `sitoUrl`.
- `inCostruzione` — when true, every page gets `<meta name="robots" content="noindex, nofollow">` (replacing `canonical`) and `robots.txt` becomes `Disallow: /`. Keeps placeholder copy and the dummy phone number out of search results. Flip to false once real content lands.

## Workflow for content changes

1. Edit `contenuti.js` (and drop photos into `img/<dog-name>/`, long side under 1600px).
2. Run `node build.js`. If it errors, fix the reported data issue in `contenuti.js` and rerun.
3. Commit and push, including the regenerated `docs/` folder.

## Deployment

Published via GitHub Pages from branch `main`, folder `/docs`.

- Repository: `allevamento-della-piancarda/allevamento-della-piancarda.github.io` (public — Pages on the org Free plan only serves public repos)
- The repo is deliberately named `<org>.github.io` so Pages serves it from the **root** of the URL. A different name would nest the site under `/<repo>/`, which breaks `404.html`'s absolute links and the `canonical`/`og:url` tags.
- Current address: https://allevamento-della-piancarda.github.io
- Target address: `https://www.cucciolidobermanpiancarda.it`, pending domain registration. To switch: set `sitoUrl` back to it, `dominioAttivo: true`, rebuild, push, then set the custom domain on the Pages settings. DNS needs 4 A records on the apex (`185.199.108.153`, `.109.153`, `.110.153`, `.111.153`) plus a `www` CNAME to `allevamento-della-piancarda.github.io`.
- `docs/CNAME` is generated by the build from `sitoUrl`, never hand-edited.
